# 托盘 GUID 不设签名门槛

| 项 | 值 |
|---|---|
| 日期 | 2026-10-31 |
| 状态 | 生效 |

## 背景

Win11 只对带 GUID 的托盘图标跨 exe 路径继承可见性偏好。上游把注册 GUID 的前提定为 Authenticode 验签通过，理由是托盘身份不应由未签名程序主张。本仓库只发未签名构建（安装包显示 `NotSigned`），这条前提等于永久关闭该机制，每次升级图标都落进折叠区。

## 决策

去掉验签门槛：非 dev 构建一律按数据家目录注册 GUID，注册失败仍回退 window/ID。

## 理由

- GUID 承载的只是「任务栏显示还是折叠」的 shell 偏好，不授予权限、不参与更新校验，不构成信任边界。
- 身份按数据家目录派生，独立实例天然分开，不会互相覆盖。
- 实测未签名 exe 能注册 `NIF_GUID` 并被 Explorer 解析（`Shell_NotifyIconGetRect` 返回 `S_OK`），门槛属策略而非平台限制。

## 备选与否决

- **门槛换成「exe 在标准安装布局内」**：多挡一层 portable 拷贝，但对正常安装用户无差别，收益不抵复杂度。
- **启动时迁移 `NotifyIconSettings` 的 `IsPromoted`**：键名是哈希、Explorer 缓存会覆盖写入、常需重启 Explorer，脆弱。
- **改安装布局（固定路径）**：托盘必须跑在拥有窗口的桌面进程里，等于放弃原子更新与回滚。
- **保持现状并提上游**：上游只发签名构建，不会采纳。

## 影响

- 本仓库与上游在 `desktop/tray_loop_windows.go` 上存在已知差异：port 上游托盘相关改动时**不要恢复 `verifyTraySignature` 门槛**。
- 上游已于 2026-11-12 归档，不再提 PR。
- 首次切到 GUID 身份时，若用户此前从无带 GUID 的条目，图标会以缺省状态出现一次、需手动固定一次，之后跨版本保持。
