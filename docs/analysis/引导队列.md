# 引导队列

输入框上方的待处理引导分两段：**本轮引导**（已受理进当前回合）和**后续队列**（等下一个回合）。两段可双向切换。

## 分组与退回

- 分组依据：`intent === "steer"` 或 `state === "steer_accepted"` 属于本轮，其余属于后续队列。
- 本轮行提供「退回队列」，后续行提供「插入本轮」；切换后重新排到目标组末尾，不恢复原位。
- 只有后续队列的行可拖拽；本轮顺序就是消费顺序，拖动会让“看着在第一却最后执行”。

**退回必须同时做两件事**：

1. Store 移到清单末尾，`Intent` 改回 `followup`；
2. `Agent.WithdrawSteer` 撤回内存里的 `steerQueue`。

只改 `State` 不改 `Intent`，前端分组会把条目跳回本轮组，表现为“点了没反应”。只改 Store 不撤内存队列，agent 稍后仍会消费该条目，回合结束会弹“本条引导未能应用”的假告警。

## 版本校验

同一队列可被桌面、HTTP 远程页、ACP 客户端同时编辑；后到的写入不能静默覆盖先到的。

- 条目 `Revision` 是“条目版本”，编辑与重排都会推进；`MoveItem` 也必须推进，否则“被移动过”检测不出来。
- 新增 `ErrRevisionConflict`；`UpdateItem*` / `MoveItem` 提供 `IfCurrent` 变体，旧调用传 0 表示不校验。
- 校验放在幂等重放之后：重复请求意味着上次已落盘，其过期版本不应判冲突。
- 冲突只做“拒绝 + 提示”，不自动重试、不自动合并。

## 派发与冻结

- 退回队列或改回 `queued` 时必须 `untrackActive`；否则回合结束的 `AckDequeue` 会拿到 `ErrInvalidState`，把行标成 `uncertain` 并暂停整个队列。
- `onInboxTurnDone` 的 ack 循环要把 `ErrInvalidState` 当“行已不归本轮”跳过；真正的 ack 失败才是其它错误。
- 不能用“队列是否为空”判断上次是否异常退出；每进程随机 `RunID` 会让正常退出也命中。manifest 记 `cleanShutdown`，只在 Controller 收尾且无活跃回合时写。
- 干净退出后，`running` / `steer_accepted` / `steer_consumed` 仍要转 `uncertain` 并暂停；只有 `queued` / `blocked` / `uncertain` 免于审查。
- 派发开关复用 `inbox.paused`，它是队列级闸门；“这条插到本轮还是排后面”是条目级属性，不要混。

## 实时刷新

`Composer` 用 `inboxSessionPath` 推导 `inboxSessionKey` 并过滤 `InboxChanged`。App 层漏传时它退化成项目级 `workspaceScopeKey`，而 `tabEventSink.InboxChanged` 携带会话文件路径，两者永不匹配，事件被静默丢弃。

- 表现为：插入时列表能更新（RPC 触发的事件不带 sessionPath，守卫放行），自动派发后列表不刷新、聊天流缺 user 消息，重开会话才恢复。
- 修法是补齐 `inboxSessionPath` 的整条传递链，不要放宽守卫；守卫是防止 A 会话事件污染 B 会话的正确约束。
- 测试必须传真实 sessionPath；传空串会命中“路径为空则放行”分支，把问题掩盖。

## followup 的 user 气泡

本轮插话走 `event.Steer`，后续队列派发走新 turn；后者原本没有投递确认，聊天流只出现 assistant 回复。

- 新增对称事件 `QueuedPromptDispatched`，带原文与 `ItemID`，前端按 `inboxItemId` 去重插入 user 项。
- 不要往 `TurnStarted` 塞文本：会膨胀 WAL ledger，且要绕开 turn 事件去重逻辑。
- 不要让前端对比快照猜哪条被派发：用户手动删/改时会产生隐式推断和乱序。

## 折叠显示

折叠时先按“本轮优先”排序，再截断到 2 条。先截断再排序会把排在存储末尾的本轮插话截掉，表现为“插了但看不见”。

## 测试教训

- 造数据要走真实入口（`AcceptSteer`），不要手写 `StateSteerAccepted`；否则 `Intent` 断言恒真。
- UI 修复要同时断言“队列状态变了”和“用户看得见”，只断言队列行会漏掉聊天流气泡。
