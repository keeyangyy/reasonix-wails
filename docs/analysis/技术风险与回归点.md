# 技术风险与回归点

来自 wails 线实际踩过的坑。改动相关代码前先读对应条目；具体提交可在仓库历史里查。

## 写工具版本校验与锚点门禁并存

`internal/fileops` 的 `RequireObserved` 已接入 `write_file`、`edit_file`、`multiedit`、`delete_symbol`、`notebookedit`，唯独 `delete_range` 不接。本仓库保留了按锚点内容匹配的 `stale_anchor_guard`，比文件版本更精确；给它加版本校验会让 anchor guard 变成死代码，CI 的 `TestDeleteRangeShadowMatchesAfterInsertionAboveTarget` 会失败。

- 新增写工具时，明确选版本校验还是锚点门禁，不要两套都绕开。
- 不要为了“统一”给 `delete_range` 加版本校验。

## 引导队列：Intent 与 State 必须同时更新

前端按 `intent === "steer" || state === "steer_accepted"` 判“本轮引导”。任何改变分组的动作都必须同时更新两者；退回队列只改 `State` 不改 `Intent`，条目会跳回本轮组，表现为“点了没反应”。

- 条目 `Revision` 是“条目版本”，编辑与重排都带 `expectedRevision`（0 表示不校验），`MoveItem` 也推进版本。
- 新增改变队列的写入路径时，走 `IfCurrent` 变体或明确传 0，别绕过 `commitManifestLocked` 直接改 manifest。
- 退回队列或改回 `queued` 时必须同时 `untrackActive`；否则回合结束的 `AckDequeue` 会拿到 `ErrInvalidState`，把行标成 `uncertain` 并暂停整个队列。`onInboxTurnDone` 的 ack 循环要把 `ErrInvalidState` 当“行已不归本轮”跳过。

## InboxChanged 的作用域

`Composer` 用 `inboxSessionPath` 推导 `inboxSessionKey` 并过滤事件。App 层漏传时它退化成项目级 `workspaceScopeKey`，而 `tabEventSink.InboxChanged` 携带会话文件路径，两者永不匹配，事件被静默丢弃。表现为后端自动派发后队列不刷新、聊天流缺 user 消息，重开会话才恢复。

- 新增事件过滤路径时，确认 sessionPath 真的传了。
- 测试不要把 `sessionPath` 传成空串；空串会命中“路径为空则放行”分支，掩盖问题。

## 队列 followup 的 user 气泡

聊天流的 user 气泡只在前端主动提交时插入（`dispatch({type:"user"})` 仅 3 个调用点），后端派发的 turn 靠 `event.QueuedPromptDispatched` 告知原文，前端按 `inboxItemId` 去重。本轮插话走对称路径 `event.Steer`。任何新增“自动启动 turn”的功能（bot、定时任务、ACP）都需要同样的投递确认，否则只出现 assistant 回复。

## 压缩卡片锚点

- 轮数锚点修过三次仍会错位：后端数 `role=user` 记录、前端渲染 user 气泡，两边对宿主注入（`<session-context>`、`<background-jobs>`、轮中插话、工具不可用提示）处理不一致；分页窗口还会让绝对轮数漂移。
- 现在 sidecar 记 `anchorMessageId`，前端按 id 定位，找不到就不显示。旧 sidecar 没有该字段 → 重启后不显示卡片，重压一次即可。
- `historyMessagesToItems` 的 user 分支必须带 `messageID`。
- 任何重建 items 的 action（`history_page` 等）都要接 `preserveLiveCompactions`，否则分页/重启丢卡片。

## 上下文用量与自动压缩

`ContextUsedTokens` 与 `ContextMaintenanceSnapshot.ProjectedTokens` 优先用 `usageAnchor`（provider 上报的 prompt 大小 + 之后的视图增量），无锚点（首次请求、fold 之后、会话重绑）才回退本地估算。这同时改变自动压缩的触发口径：以前偏保守，现在以 provider 实测为准。

## 托盘 GUID

`trayIdentity` 不再要求 Authenticode 验签——只发未签名构建，保留门槛等于每次升级都把托盘图标打回折叠区。port 上游托盘改动时不要恢复 `verifyTraySignature`。理由见 [决策](../decisions/20261031-托盘GUID不设签名门槛.md)。

## 侧栏会话列表

`catalogRuntimeSnapshots` 同时遍历 `a.tabs` 与 `a.detachedSessions`，两个 map 之间原本不去重；同一会话切走标签后会同时留在两处，被投影成两行同名条目。新增遍历这两个 map 的投影逻辑时，按 `sessionRuntimeKey(path)` 去重。

## tabEventSink 必须带 ctx

`emitRuntimeEvent` 在 `ctx == nil` 时静默丢弃事件，导致该标签在后台完成时不播提示音。新增创建点时一律带 `ctx: a.ctx`，不要指望后续 `setContext`。

## 价格显示

账本里只要有一条报价 `Complete=false`，整场聚合就是 `costFactsComplete=false`，前端显示“不可用”。排查先看 `%APPDATA%\reasonix\stats\<日期>.jsonl` 的 `incomplete_reason`：

- `missing_price_or_usage`：该调用根本没有 token 数据；
- `no_price`：没配价格。

修法两侧都要：入库侧不再为无 token 调用生成报价；读取侧聚合跳过没有 token 计数的桶。只改入库侧救不了已落盘的历史账本。

## CI 与发版

- CI 监听 `main`；改 workflow 触发条件后，用 `gh run list --workflow=ci.yml` 确认真有 run 产生。
- 前端有两套类型检查：`tsconfig.json` 与 `tsconfig.test.json`；只跑前者会漏测试文件的类型错误。
- 在 Windows 上用 `GOOS=linux golangci-lint` 会编进 `!cgo` 分支，报出 CI 上不存在的 `unused`；判 lint 真假以 CI 的 linux 腿为准。
- 发版只有 `release-manual` → `release-windows` 一条链；tag 形如 `vX.Y.Z` 或 `vX.Y.Z-beta.N`。`release-manual` 会先等该提交 CI 变绿再打 tag。
