# 工程协作与自动化经验

只保留经过实际验证、可跨任务复用的工程经验；当前必须遵守的操作约束见项目专项规则。

## 多会话共享 worktree

- `git worktree list` 只能核对 worktree 路径、检出分支或 detached HEAD，不能判断哪个会话正在使用，也不能证明独占。
- 检查之后仍可能有其他会话切换或修改同一 worktree；并行作业应另行协调占用，避免把快照当锁。
- 曾发生未提交改动被抹掉、只剩未跟踪新文件的事故；同一 worktree 的 index 也可能被其他会话的 `git reset` 影响。
- 识别线索：当前分支与预期不符；`git reflog` 出现 `checkout: moving from <你的分支> to <别处>`。
- 处理时不要覆盖或 reset 其他会话的 worktree；切换到空闲 worktree 重放，并尽早提交检查点。

## GitHub Actions 事件与权限

- 由 `GITHUB_TOKEN` 推送的分支或 PR 不会自动触发后续 `push` / `pull_request` workflow；需要链式执行时显式使用 `workflow_dispatch` 或 `repository_dispatch`，例如 `gh workflow run <wf> --ref <branch>`。
- `schedule` 在默认分支执行；`workflow_dispatch` 的工作流文件必须已存在于默认分支（本仓库为 `main`）才能手动触发，但 `gh workflow run <wf> --ref <branch>` 会选择指定分支上的 workflow 版本执行。
- `GITHUB_TOKEN` 不能推送修改 `.github/workflows/**` 的提交；这类提交需要使用含 `workflow` 权限的 PAT 或 deploy key。
- 修改触发条件后，应确认实际产生了预期的 workflow run，而不只检查 YAML。

## pnpm 与构建环境

- 本机曾因 pnpm 11 出现 `ERR_PNPM_IGNORED_BUILDS` 并生成额外 workspace 文件；按仓库 `packageManager` / `engines` 使用 pnpm 10。
- 构建产物、缓存和临时目录不进入版本控制；测试结束清理中间文件。
