# 会话归属与身份

多条线共用 `%APPDATA%\reasonix`，本仓库需要能识别自己的会话、不碰外线会话，并以独立身份访问外部服务。

## 会话归属

- 本仓库新建会话在保存时**盖章**（归属字段），不按目录或时间猜归属。
- 列表与对账阶段直接丢弃外线会话（`dropForeignSessions`），不只是归类：不列出、不打开、不静默迁移。
- 归属为空的旧会话保持现状，不自动迁移，避免误改历史归属。
- 本仓库重写 sidecar 时保留未建模字段（`archived` / `pinned` / `auto_archived_at` / `finished_at` / `viewed_at` / `superseded` / `imported_from`），不要擦掉另一条线写入的状态。
- 会话列表 30 秒周期闪动由 `SyncMetadata` 的幂等守卫消除；不要用节流掩盖。

## 会话文件名安全

会话文件名由“时间戳 + 模型标签”拼成，模型标签是不可信输入，可能含 `/`、`\`、`..`、NUL 或超长内容。

- 在**文件名分量**层面校验：禁路径分隔符、`..`、保留标点、控制字节、超长。
- 非法时回退为带时间戳的通用名，绝不带标签出目录。
- 不动目录层级；长度上限要含时间戳前缀与 `.jsonl` 后缀。

## 客户端身份

模型请求的 UA 优先级：**provider 自定义 headers > opencode 固定值 > `Reasonix-Wails/<version>`**。

- opencode.ai 端点要求 UA 恰好是 `Reasonix-Wails`（不带版本），兜底必须放在 opencode 规则之后，否则破坏契约测试。
- 自定义 UA（如 `claude-code/0.1.0`）不会被覆盖；`ApplyClientIdentity` 只在 UA 为空时补。
- MCP `clientInfo.name` 与 ACP agent name 用 `reasonix-wails`。
- 更新器 UA 保留 `Reasonix-Updater/<version>`：只访问本仓库 release，版本自成体系。
- `%APPDATA%\reasonix\install-id` 仍与上游共用；桌面端不读它，不产生上报。

## 会话指纹自愈

会话有两份元数据：权威的 `<会话>.jsonl.meta` 与派生的 `<会话>.display-index.json`。正文被同尺寸重写而 meta 的 `content_digest` 未同步时，索引永远被判无效，读取退化成“内存回退 + 排队重建”，重建还是同一指纹，形成自指死锁。

- 体检工具：`reasonix doctor fingerprint`，区分 `ok` / `stale-meta` / `stale-index` / `foreign-schema` / `damaged` / `unreadable`。
- 桌面端自愈默认关闭，需 `REASONIX_SESSION_FINGERPRINT_SELFHEAL=1`；只在“meta 自称有权威身份、且指纹与实际内容不符”时接手。
- 复用 `agent.RepairSessionListingProjection`，不新写对齐逻辑。
- **`stale-meta` 不是“不能读”**：它表示 meta 与 index 共同指向同一个过时标签，索引仍可用；只影响标签准确性。

### 分页失败的恢复

- 恢复入口原本排在分页成功之后，分页失败直接返回，形成“修复等分页成功、分页成功等修复”的死锁。
- 现在分页失败时同步重建读模型再试一次；只重建可重放的会话，其他线/新 schema 不动。
- 失败与恢复都写 `slog.Warn`，带 `cause` 与 `recovered`；前端把真实错误挂到文案与重试按钮的 `title`。
- 真实病因尚未复现；本次修的是恢复能力，等复发时由日志给出原因。

### 排查教训

- fixture 必须与生产文件集一致。曾漏掉 `.events.jsonl`，导致走错分支、复现出假问题；差异一旦落在“决定走哪条分支”的字段上，结论会整个翻转。
- 不要因为名字像病因就下结论；先验证该状态是否真的影响读取。

## 侧栏去重

`catalogRuntimeSnapshots` 同时遍历 `tabs` 与 `detachedSessions`，两个 map 之间不去重；同一会话切走标签后会同时留在两处，被投影成两行同名条目。新增遍历这两个 map 的投影逻辑时，按 `sessionRuntimeKey(path)` 去重。
