# 读证据链：文件观察与写入校验

调研结论：**不要移植 `readcoord`；用文件观察（file observation）按“目标版本”授权写入。**

> 基线：2026-10 调研，上游 v1.38.2→v2.46.0。上游已停维；本文保留机制结论，具体实现以本仓库当前代码为准。

## 一、三代机制

| 代际 | 版本 | 包 | 思路 | 结局 |
|---|---|---|---|---|
| 一代 | v1.38.3–v1.38.7 | `internal/readcoord` | 追踪“读了多少行”，覆盖不全就续读/阻塞 | 造成写入死锁，v1.38.12 废弃 |
| 二代 | v1.38.12–v1.39.x | `internal/fileops` | 追踪“这个文件的哪个版本被看过”，写前校验版本 | 机制稳定，推荐 |
| 三代 | v2.x | `internal/state/observation` | 每回合对整个工作区做内容寻址快照，按子树摘要 diff | 更重，依赖 `trustedstate`，本仓库不需要 |

上游废弃一代的原因很明确：**用“读过哪些行”授权写入是错的，应该用“写入目标的哪个版本”授权。**

## 二、二代机制

### 数据结构

```go
type Target struct { Route, Key, Path string }   // Route: disk / overlay
type Version string                               // 宿主生成的不透明版本
type Observation struct { Kind; Version }         // Unseen / Absent / Present(version)
type Store struct { items, paths map[string]Observation }  // 内存表，不序列化
```

### 缓存

- 进程内内存表，挂在 agent 会话上；`items` 用原生文件身份，`paths` 用规范化路径兜底。
- 不落盘、不进 transcript；会话恢复/分叉/回退时清空；同一进程内 runtime 替换用 `Clone()` 迁移。
- 不做磁盘缓存：磁盘版本随时会变，持久化缓存会给出过期断言。

### 版本

版本只由元数据生成，不读全文：

```
size + mode + mtime + Windows 原生字段（volume serial / file index / change time）
→ sha256 → "disk-v1:<hex>"
```

Windows 原生字段是核心：没有它们，无法识别“路径不变但文件被替换”。读身份要取实际打开的句柄，防止 TOCTOU。

### 写入校验

```go
if obs.Kind == Unseen      { return FS_NOT_OBSERVED }
if obs.Version != current  { return FS_STALE_VERSION }
// 校验通过 → 目标锁内原子替换 → 记录新版本
```

- 257 个条带锁，按 `route + key` 与 `path` 双键散列，稳定排序避免死锁。
- 新建文件用不覆盖的原子创建；已存在则校验版本后原子替换。
- 连续编辑不需要重读：成功写入直接记录新版本。

### 读侧

`read_file` 成功后记录 `ObservePresent(target, version)`；读失败不记录；确认不存在记录 `Absent`。模型永远拿不到版本值。

## 三、本仓库的演变

调研时本仓库只有 `delete_range` 的锚点安全门禁（按读行内容哈希判断），没有统一的文件版本校验。后续 `internal/fileops` 的 `RequireObserved` 已接入 `write_file`、`edit_file`、`multiedit`、`delete_symbol`、`notebookedit`；`delete_range` 仍保留锚点门禁，不接版本校验。两者并存的回归点见 [技术风险与回归点](技术风险与回归点.md)。

## 四、移植/维护要点

- 不移植 `readcoord`：已废弃，会带来写入死锁。
- 不移植三代工作区快照：依赖 `trustedstate`，成本远超收益。
- 不用内容哈希做版本：大文件窗口读会退化成全文件扫描。
- overlay（未保存缓冲区）要单独一条 route，不能与磁盘版本混用。
- `Absent` 是独立状态，不是“没有记录”；新建文件必须先确认不存在。
- 新增写工具时，先决定它走 `RequireObserved` 还是锚点门禁，不要两套都绕开。
